# KRX 이력과 대시보드 알림

## 저장과 조회

- `krx_gold_history`: 거래일·상품별 검증된 KRX 일별 원자료. 기본키 `(symbol,trade_date)`로 중복을 방지하며 상품별 기간 조회와 정렬에 사용한다.
- `krx_gold_days`: 정상 조회한 날짜와 자료 유무. 빈 휴장일을 장애와 구분하고 재시작마다 같은 이력을 다시 요청하지 않는다. 실패한 요청은 완료로 표시하지 않는다.
- `dashboard_system_state`: 공급자/수집기별 상태 네 행. 리스 소유 수집기만 상태를 갱신한다.
- `dashboard_system_events`: 실패·복구 전환과 수집 공백을 기록한다. 같은 장애가 지속되는 동안 반복 기록하지 않는다. 시간 내림차순 복합 인덱스로 최근 100건을 조회하며 90일 초과 이력은 수집기가 삭제한다.

마이그레이션: `ops/sql/create_history_and_alerts.sql`. 기존 테이블과 토큰 정책을
변경하지 않는 추가 마이그레이션이다. 네 테이블 모두 RLS를 활성화하고
anon/authenticated 권한을 철회한다. 웹에서는 FastAPI만 읽고 서비스 키는
백엔드에만 둔다. 공개 설정 변경 API는 만들지 않는다.

실시간 스냅샷은 계속 한 행을 교체하며, 장기 일별 이력과 분리한다. 매 요청에
공급자를 호출하지 않는다. 새 조회 API는 전체 사용자에 공유되는 15초 캐시로
동시 요청을 합치고, 상품 두 개와 기간 두 개로 캐시 키 공간을 제한한다.
이력과 알림 조회는 각각 읽기 전용 DB 함수 한 번으로 처리한다. 조회 종류별
캐시 잠금을 분리해 느린 이력 조회가 알림 조회를 막지 않게 한다.

- `GET /api/krx-gold-history?symbol=04020000&days=90`: 30/90일, 두 금 상품만 허용. 최대 366행으로 제한한다. 실제 거래일 자료와 평일 조회 완료 건수를 반환한다. 당일 자료 미제공과 미완료 과거 이력을 UI에서 숨기지 않는다.
- `GET /api/system-alerts`: 최신 스냅샷이 만료돼도 서버의 알림 이력을 읽을 수 있다. 스냅샷이 90초 넘게 갱신되지 않았으면 안정된 ID의 지연 알림을 합친다.

수집기는 일별 자료가 갱신될 때 중복 없이 저장하고, 실시간 스냅샷을 먼저
게시한 후 사이클당 과거 날짜 한 개만 보충한다. 오류 시 5분간 재시도를 늦춘다.
최초 보충은 `backend/venv/bin/python ops/backfill_krx.py --days 90 --from-render`로
수행할 수 있다. 이 명령은 기존 Render의 등록 키를 메모리에서만 사용하며
실시간 스냅샷·KIS 토큰·리스 소유권을 변경하지 않는다. 재실행 시 정상 조회한
날짜는 건너뛴다.

## 차트

30/90일과 금 1kg/미니금 100g 선택, 종가 선 및 거래량 막대, 포인터·키보드
날짜 탐색, 거래일별 원자료 표를 제공한다. 화면 폭에 맞춰 좌표계를 조정한다.
없는 가격은 연결하지 않고, 한 개뿐인 종가로 등락률을 계산하지 않는다.
거래량 단위는 g, 종가는 원/g이다. 차트는 5분마다 저장된 자료를 다시 확인한다.

## 알림함

가격 조건은 로그인 없는 공개 대시보드의 다른 방문자와 섞이지 않도록
브라우저 저장소에 보관한다. 최대 10개 조건, 국내 금 현물 원/g와 국내외
가격 차이 %, 이상/이하 비교를 지원한다. 등록 시 이미 충족하면 한 번 알리고,
충족 상태가 지속되면 반복하지 않는다. 새로 진입할 때도 같은 조건은 최소
10분 간격을 두며, 실패하거나 90초 지난 시세로 조건을 평가하거나 재무장하지 않는다.

조건은 화면이 열려 있는 동안만 평가한다. 외부 채널·닫힌 브라우저에서의
가격 알림·브라우저 푸시는 제공하지 않는다. 조건, 최근 100건의 알림,
읽음 상태는 브라우저마다 유지한다. 일시 중지·삭제·종류 필터·모두 읽음을 지원한다.
저장소가 차단되면 유지할 수 없다는 안내를 보여준다.

서버는 금 시세·선물·KRX 실패와 복구를 기록한다. 거래 없음/휴장과 실제 조회
실패를 구분하고, KRX는 기준 거래일이 아닌 마지막 성공 조회 시각을 확인한다.
서버 API 연결을 30초 이상 확인하지 못하면 열려 있는 화면에서 로컬 경고를
추가하고, 연결 복구 시 복구 알림도 남긴다.

기존 무료 Render 서비스가 중지되면 수집기도 중지된다. 외부 감시기가 따로
없으므로 중단 중에는 서버 이벤트를 즉시 작성할 수 없다. 접속 시 지연을
표시하고 수집기 복구 시 공백과 복구를 서버에 기록한다. 별도 Worker 분리는
추후 작업으로 유지한다.

## DB 점검 결과

2026-11-12 점검에서 기존 앱 테이블/인덱스 합계는 약 424KiB였으며 최신 시각
조회에 필요한 기존 인덱스가 있었다. 최근 90일의 58개 거래일·두 상품을
저장한 후 전체 앱 테이블/인덱스는 약 608KiB였다. 이 수치는 DB 전체 사용량이
아니라 public 앱 테이블과 인덱스의 측정값이다. 모든 테이블의 RLS와
anon/authenticated 조회 차단을 확인했다.
90일·한 상품의 실제 조회 계획에서 복합 기본키 인덱스 사용을 확인했으며,
58행 조회의 DB 실행 시간은 약 5.4ms였다(해당 측정 1회, 네트워크 시간 제외).

현 규모에서는 파티셔닝·추가 DB 서비스·기존 테이블 삭제가 필요하지 않다.
`gold_prices`에 구형/신형 필드가 함께 있지만 현재 FastAPI 조회는 단일
스냅샷을 사용한다. 해당 구형 테이블은 운영 경로의 병목이 아니며, 롤백
호환성이 필요 없어졌을 때 별도 마이그레이션으로 정리하는 편이 적절하다.
